# 弦记 OMR 平台：切图标注首版设计

日期：2026-10-22（Asia/Shanghai）

## 1. 用户确定的产品边界

最终产品是弦记 OMR 的数据标注、数据管理、训练记录和模型管理平台。平台不承担模型训练计算：用户在本地拉取平台上已标注的数据，使用本地 CPU/GPU 训练，再把模型权重、配置和评测结果上传回平台。

本轮只实现其中的「数据集 → 原图切图标注 → 确认 → 可供本地训练的数据导出」。当前的通用矩形编辑器是可复用的编辑基础，需要补齐曲谱数据集语义。本轮不实现本地训练器、训练任务页面、模型上传页面、自动识谱或谱面 JSON 转换。

用户最近两条要求是本设计的依据：

> 这个平台最终应该是完整的数据标注和训练、模型管理，只不过现在只做切图标注的能力。

> 标注、数据管理、训练出来的模型管理是在平台上，但是训练是本地拉取平台标注的数据，在本地用本地资源训练，训练好之后将模型权重等内容传到平台上。

## 2. 实现路径选择

采用在现有云端工程中分模块扩展的方式，保留已部署的登录、原图编辑、私有 OSS、PostgreSQL 和部署脚本。这样当前工作能直接形成训练资产，后续只需接入消费这些资产的本地训练端和模型管理模块。

另一种路径是接入通用标注框架，再开发谱行关系、数据版本和云存储适配器。其通用标注功能更丰富，但当前已有所需的框编辑能力；引入第二套身份和数据模型会增加本阶段成本。因此本轮采用现有项目扩展方案。

## 3. 端云分工与交接资产

长期数据流：

```text
平台上传原图、组织曲目
    → 平台切图标注、确认
    → 平台冻结一个数据版本并导出
    → 本地下载并校验数据包
    → 本地训练、验证、测试
    → 上传模型权重、配置、指标等产物
    → 平台关联数据版本并管理模型版本
```

本轮的交接资产是可下载的、不可变的数据快照。它不能是一个会随编辑变化的图片列表，也不能只是没有类别的矩形 JSON。后续模型至少能记录其使用的 `snapshotId`、数据指纹和类别版本；训练参数、代码版本、运行环境、权重校验值及评测报告也应与该快照关联。这些训练和模型实体的实现留给后续独立设计。

当前通过已登录的页面下载导出包。未来本地工具的自动拉取和模型上传使用平台认证，不把 OSS AK/SK、数据库密码或管理员会话塞入训练包；本轮不提前实现机器令牌或训练调度系统。

## 4. 首版界面和操作

### 4.1 数据集和曲目

- 数据集列表提供名称、曲目数、图片数、待标注数、已确认图片数及框数。
- 创建数据集后，按曲目上传多张图片；支持批量选文件、显示逐文件进度和失败重试。
- 每张图片有曲目、页序、原文件名、尺寸、校验值和标注状态。可以修改曲目归属和页序，不根据 `page-01` 等重复文件名猜测曲目身份。
- 同一首歌的不同页面、不同谱本用显式 `songGroupKey` 关联。首版提供编辑分组和曲目级 train/val/test 用途的入口，不能按单页随机切分。
- 首版不提供批量物理删除原图或数据集的操作，避免扩大生命周期管理范围；标注框可以正常删除。

### 4.2 标注工作台

- 左侧为当前曲目的页面缩略图与标注状态，中间为原图画布，右侧为标签、框列表和选中框属性。
- 支持画框、选择、移动、角点缩放、删除、撤销/重做、缩放和平移；继续使用原图像素坐标，视图缩放不改动标签坐标。
- 画框前可选当前类别；已画框可修改类别、所属谱行和坐标。类别有固定颜色，选中框与右侧列表同步高亮。
- 快捷键沿用 V/R/H、空格平移、Delete、Ctrl/Command+Z；数字键选择类别。输入文字或坐标时不触发画布快捷键。
- 提供上/下一页、保存草稿、确认本页、取消确认、导出数据入口。
- 离开有未保存改动的页面时提示保存或保留草稿。云端保存成功与仅存浏览器草稿必须明确区分；失败时保留用户改动。
- 裁片预览展示选中框实际包含的内容，帮助检查是否裁掉附属符号。首版不接入自动检测或自动批量确认。

### 4.3 当前训练目标与类别

首版训练目标是「定位完整谱行及其区域」，不是识别裁片里的音符内容。沿用现有本地布局模型的七类，并冻结类别编号：

| YOLO class id | key | 页面名称与边界定义 |
|---|---|---|
| 0 | system | 完整谱行：覆盖本行有关的和弦、谱表、简谱、歌词等内容 |
| 1 | guitar | 六线谱：含六根弦及属于该谱表的上下节奏、技法符号 |
| 2 | melody | 简谱：含音级、八度点、减时线、附点、升降号等附属符号 |
| 3 | lyrics | 歌词区域：保留本行所有段落歌词及末尾单字；无需逐字画框 |
| 4 | chord_marks | 和弦、指法图及其他音乐标记区域 |
| 5 | staff_notation | 五线谱及附属符号区域 |
| 6 | other_tab | 四线、五线或其他非六线弦乐谱表区域 |

类别版本固定为 `layout-v1`。COCO 的 category id 为上述 id 加 1；原生 JSON 保留 key，导出包保存两者映射。首版不允许任意更改类别编号或加入内容标签。

`system` 为根框；其他区域通过 `parentSystemId` 关联完整谱行。谱页全局的 `chord_marks` 可以没有父谱行；其余子类确认时必须有关联。一个完整谱行可有多个同类子框。父框需要包含关联子框；子框之间允许有意义的重叠。纯说明、插画或空白页可以明确确认为负样本，不能把尚未标注的音乐页当作负样本。

标题和作者等信息不强行塞入音乐区域类别；其独立 OCR 标注任务留待后续扩展。

## 5. 数据结构、保存与版本

本轮新增的数据实体控制在以下范围：

- `Dataset`：名称、说明、任务类型 `layout`、类别版本、创建/更新时间及元数据版本。
- `Song`：所属数据集、曲目名称、显式分组键、用途 train/val/test、页序关系和版本。同一数据集内相同分组键的曲目必须使用同一用途。
- `Image`：保留原图及校验值，关联数据集、曲目和页序，记录尺寸、坐标图像标识、版本、标注状态和页类型。
- `Region`：稳定 id、类别 key、整数 `{x,y,width,height}`、父谱行 id、阅读顺序。与页面标注作为一个原子版本保存，沿用现有 JSONB 能力，不为每次拖动创建数据库行。
- `DatasetSnapshot`：不可变的图片和标签清单、来源版本、类别版本、分组划分、统计、数据指纹及导出产物标识。

页面标注状态为 draft/confirmed；页面列表中无有效标注的 draft 显示为「待标注」。页类型为 music/negative。确认 music 页必须包含有效目标区域；确认 negative 页必须明确声明该页没有七类目标区域且框数为零。

确认代表用户已检查本页的全部目标区域。服务端验证类型、类别、唯一 id、整数边界、父子关系和版本；无法仅靠几何检查保证没有漏标，页面需要给出该确认含义。

所有页面写入带预期版本号。编辑已确认页面的标注、坐标图像、曲目归属或页类型时，原子地取消确认。曲目分组和 split 的修改增加曲目版本，在新快照中重新验证，不改动既有快照。409 冲突时不得覆盖服务端版本，保留本地草稿并允许导出备份。

### 5.1 原图与坐标

原始上传字节不可变。普通无 EXIF 旋转图片直接使用原图坐标；带 EXIF 旋转/镜像的图片生成确定性的、移除方向标签的工作图，工作图只进行方向修正，不缩放。界面与检测训练均使用同一坐标图像；清单保留原图和工作图各自的尺寸、校验值、方向变换及坐标版本。

内部和原生导出统一为左上原点、整数 xywh、右/下边界不包含在区域内的半开区间。切图不得额外加不可追踪的 padding。将来需要 padding 时，应另存裁片框及变换，不能修改人工标注真值。

### 5.2 既有数据兼容

- 云端已有图片和无类别矩形进入「历史未归类」数据集，保留图片 id、对象、框 id、几何和版本；状态为 draft。用户补充曲目、类别及关系后才能确认，不能自动假设原有框属于某个类别。
- 当前浏览器的本地草稿不自动覆盖或静默迁移。新版检测到旧草稿时提供恢复入口，保留原草稿直到用户成功保存；旧导入文件按新的待确认文档处理。
- 保留旧读取和图片下载能力；旧格式写接口只能修改尚未升级的 legacy 草稿。对已转为有类别标注的页面，旧客户端 PUT 返回明确的版本/格式冲突，避免旧 `validateBoxes` 静默剥掉类别和父子信息。
- 数据库迁移采用新增表/列的方式，保留原图片、会话和版本；迁移前备份专用 OMR 数据库。不能依赖旧程序能安全写入新标注结构。

## 6. 可供本地训练的数据导出

### 6.1 冻结快照

用户选择一个数据集，点击导出。平台展示确认页数量、框数量、各类别和 train/val/test 分布，以及待标注/草稿未纳入的数量。

在一个一致性数据库事务中复制已确认页面的原图身份、标注版本、曲目版本、全部框和分组划分，生成不可变快照。之后的图片与裁片读取基于这个清单，不能在打包过程中重新读取可变的当前框。人工修订生成后续快照，原快照不随之改变。

同一原图校验值在一次导出中只出现一次，并保留全部别名来源、曲目关系和来源版本。去重前必须核对坐标图像身份、页类型及规范化标注内容：比较类别、整数几何、父子拓扑和阅读顺序，忽略记录 id 的差异。坐标图像不一致或标注内容有差异时，拒绝导出并列出冲突页面，要求用户回到标注页解决；不得任选一份、合并框集合或用较新版本静默覆盖。只有内容一致时才以稳定排序的首个 image id 为代表输出一张训练图，并保留全部来源映射。

如果相同图像或相同曲目组跨 split，拒绝导出并指出冲突；不同文件的相同歌曲/版本由显式分组键约束，首版不声称自动发现所有翻唱、改编或近似重复。快照分别记录已确认来源页数、去重后训练图数及各自的框数，界面和完整性报告使用相同口径。

没有已确认页面时拒绝导出。仅有 train 时可以导出，但标明没有独立验证/测试部分，不提供评测就绪的表述。已导出的测试版本保持不变；修改后生成的是新快照，不复写旧测试标签。

### 6.2 数据包内容

一个快照包含两个用途明确的产物：

1. **检测训练数据包**：坐标图像、每张图的 YOLO 标签、COCO annotations、原生完整标注 JSON、类别映射、分组和 split、数据清单及完整性报告。原始上传图也作为来源资产包含；工作图与原图相同时只存一份并在清单引用。六线谱/歌词等区域框以整页图上的标签训练检测器。
2. **裁片包**：由快照区域框精确生成的 PNG，以及每块裁片的 region id、类别、原图/工作图身份、框、父谱行和坐标映射。裁片包用于后续内容标注和识别模型准备，不能声称已具备品位、时值或歌词文字真值。

`manifest.json` 至少含 `schemaVersion`、`snapshotId`、`datasetId`、`task`、`taxonomyVersion`、`categories`、`images`、`songs`、`splits`、`sourceRevisions`、`fileChecksums` 和 `datasetFingerprint`。数据指纹由确定性排序后的规范清单生成，计算时排除自身指纹字段和易变下载信息。OSS object key 只在服务端解析；导出清单用包内相对路径，不包含密钥、会话或永久公开 URL。

本地验收程序需要能验证文件校验值、类别编号、坐标范围、父子关系和分组划分，读入 YOLO/COCO 后回到原坐标的误差小于 0.01 像素。不能只检查 ZIP 能打开。

### 6.3 打包与资源边界

导出由后端复制快照、逐图生成所需文件并打包，任务状态为 preparing/ready/failed。UI 只在数据集内展示该次导出的进度、结果和重试；本轮不建设通用任务调度页面。

后端同一时刻只执行一个导出，图像处理并发为 1，逐文件流式压缩和上传，不把整包或全数据集图片载入内存。显式设定受限的 sharp 缓存/线程与单页像素检查。失败标记该导出不可下载，保留原图和标注，清理仅属于该导出的临时文件；允许用同一冻结清单重试。只有产物完整、校验通过并写入完成标记后才提供下载，进程重启后将未完成任务标为可重试失败，不能显示为已完成。

快照登记与快照 manifest 存 PostgreSQL，完成的数据包存现有私有 OSS `omr/` 前缀。下载必须经过现有登录校验；不开放 bucket 公开读写。首版不实现数据包生命周期删除，平台新增存储占用需可见。

## 7. 工程边界与部署

当前后端为 Node/Express + PostgreSQL + sharp + 私有 OSS；前端为原生 HTML/JS。保持该栈，本轮不引入新的前端框架或 Python 训练环境。

按照 dataset/song、annotation、export 拆分后端模块；从单个 `web/index.html` 抽出本轮需要的页面路由、API 客户端、画布和状态模块。此拆分服务于标注工作流，不做无关重构。身份认证与现有配置方式保持统一。

部署目标仍为 `xianji-omr` 独立服务、专用数据库和 OSS 前缀。共享 ECS 上不安装/运行训练器，不修改现有弦记服务的配置、数据库、端口、systemd 单元或发布目录。数据库迁移使用 OMR 专用连接和备份，检查失败则不切换应用发布。

## 8. 验证与验收

1. 上传一首多页真实曲谱，页序和分组可调整，上传失败可逐项重试。
2. 在原图画出完整谱行及其子区域，移动、缩放、改类别、删除、撤销/重做后，保存、刷新、重新打开保持一致。不同视图缩放不改变原图标签。
3. 在存在 EXIF 方向、透明通道和长图的样例上核对显示、标注、裁片与训练图像使用相同坐标。
4. 草稿不纳入训练包；缺类别、错误父框、越界、重复 id、非法负样本被拒绝确认。修改已确认页后必须重新确认。
5. 两个客户端编辑同页产生明确 409 且保留草稿；旧格式客户端不能抹掉已升级的标签。
6. 快照后继续编辑标签，旧快照不变；同曲组或同图跨 split 被拒绝。同图同 split 的等价标注去重且保留来源，不同标注阻止导出。来源页数、唯一训练图数和框数均与快照相符，裁片与原图映射可回验。
7. 一个隔离的本地验收脚本能解压数据包、核对校验值并读入原生/YOLO/COCO 标签；这验证训练输入可用，不等于已经训练或识谱准确率提高。
8. 在隔离数据库和对象存储中测试迁移、回读、版本冲突、导出失败/重试和备份恢复，再检查真实页面操作。禁止用生产图片做会覆盖或删除的自动测试。
9. 完成适用测试、构建和浏览器验收后推送 `qkiroc/xianji-omr` 并部署。验证新服务健康及现有弦记健康，不重启现有弦记服务。

## 9. 后续阶段说明（本轮不实现）

下一阶段独立设计本地训练工具：从平台下载指定快照，在本地校验和训练，生成可追溯训练产物。

再下一阶段独立设计训练记录及模型管理：上传权重、模型配置、环境和评测报告，关联数据快照与类别版本，展示真实指标、版本与适用范围。平台显示本地训练的报告状态，不伪装在服务器上执行训练。

随后才能扩展事件内容标注、歌词 OCR 校对等任务；这些任务拥有各自的标签结构，不能从本阶段的区域类别直接推导内容真值。
